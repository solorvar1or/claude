# Сайт WOODGER

MVP сайта по архитектуре из [`docs/woodger/site-architecture.md`](../docs/woodger/site-architecture.md).
Статический сайт на [Astro](https://astro.build) + PHP-обработчик форм.

## Запуск

```bash
npm install
npm run dev      # http://localhost:4321 (формы в dev не отправляются — нет PHP)
npm run build    # готовый сайт в dist/
```

Проверить формы локально: `php -S 127.0.0.1:8099 -t dist` после сборки
и файл `dist/send.config.php` с `return ['dry_run' => true];` — заявки пишутся в `dist/send-log/`.

## Плейсхолдеры

Всё, что нужно уточнить у WOODGER, записано как `[[текст]]` и подсвечивается жёлтым на страницах.
Перед запуском не должно остаться ни одного:

```bash
grep -rn "\[\[" src/
```

## Где что менять

| Что | Файл |
|---|---|
| Телефон, мессенджеры, адреса, режим работы, реквизиты, домен, ID аналитики | `src/data/site.ts` |
| Категории, тексты посадочных, материалы, факторы цены | `src/data/categories.ts` |
| Проекты портфолио (сейчас — демо-шаблоны) | `src/data/projects.ts` |
| Этапы заказа, FAQ, отзывы, команда | `src/data/content.ts` |
| Временное оформление (цвета, шрифты) | `src/styles/global.css` — переменные в `:root` |

Фото проектов кладутся в `public/projects/<slug>/` и указываются в поле `photos` проекта.
Пока фото нет, выводятся заглушки с подписью, что именно нужно снять.

Категория из раздела «Корпусная мебель» становится отдельной страницей, когда у неё
набирается 3–4 проекта: в `categories.ts` поставить `page: true` и заполнить поля посадочной.

Домен (`https://woodger.by` — **нужно подтвердить**) указан в трёх местах:
`astro.config.mjs`, `src/data/site.ts`, `public/robots.txt`.

## Формы

Все формы отправляются на `public/send.php` (заявка на почту с вложениями и/или в Telegram).
На хостинге рядом с `send.php` создать `send.config.php` по образцу `send.config.example.php`
(файл не хранится в git). Нужен хостинг с PHP 8.1+.

Цели аналитики (Яндекс.Метрика / GA4) отправляются автоматически, если в `site.ts` указаны ID:
`lead_<форма>`, `form_start_<форма>`, `calc_step_N`, `call`, `messenger`, `route`, `cta_*`.

## Что сознательно не сделано

Визуальный дизайн — текущее оформление нейтральное и рабочее; финальный дизайн меняет
только `global.css` и разметку компонентов, структура и данные остаются.
